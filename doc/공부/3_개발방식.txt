waterfall 방식
  : 순차적(순서대로)
  : 요구사항 분석 -> 설계 -> 구현 -> 테스트 -> 유지보수
  : 단계가 끝난 후 다음 단계로 이동
  : 프로젝트 범위, 비용, 일정 예상 가능
  : 관리 및 통제 쉬움
  : 이전 단계로 돌아가기 어려움
  : 초기 계획에 문제가 있어도 수정 어려움
  : 큰 프로젝트에 주로 사용됨

애자일(agile) 방식
  : 프로젝트를 여러 개의 짧은 개발 주기(스프린트)로 쪼개고 분석,설계,구현,테스트 반복
  : 고객, 팀원과 소통이 중요
  : 요구사항 반영 쉬움
  : 전체 계획 예측 어려움

블랙박스 테스트
  : 기능 중심. 입/출력만을 검사로
  : 동등 분할 - 입력값을 분류해 그룹별 대표값만 테스트
  : 경계값 분석 - 입력값의 경계에서 오류가 발생하는지 테스트

화이트박스 테스트
  : 구조 중심 테스트. 내부 코드 구조 및 논리 분석
  : 제어 흐름 검사 - 코드의 모든 경로를 실행해 오류가 없는지 확인

경험 기반 테스트
  : 테스터의 경험과 직관에 의존

정적 테스트
  : 프로그램 실행하지 않고 테스트

동적 테스트
  : 프로그램을 실행해서 테스트

개발 프로세스 단계
  1. 계획
  2. 요구사항 분석
  3. 설계
  4. 구현
  5. 테스트
  6. 배포, 유지보수
