@Controller : HTML 뷰 반환
@RestController : @Controller + @ResponseBody

Multipart : 텍스트/바이너리 데이터 등을 하나의 HTTP 바디에 넣어 보냄
MultipartFile : 각 파일을 캡슐화한 객체

서블릿 : WAS에서 실행되는 자바 클래스
  웹 어플리케이션에서 요청-응답 사이를 담당
  서버가 실행되고 첫 요청이 들어오면 새 서블릿 인스턴스 생성
  생성된 서블릿 인스턴스는 모든 요청을 처리
서블릿 컨테이너 : 서블릿 객체의 생명주기 관리
  최초 요청 시 서블릿 클래스를 메모리에 로드, 객체 생성 및 init()메소드로 초기화

WS(웹 서버)
  : 정적 콘텐츠(이미지, 동영상 등) 응답

WAS(웹 어플리케이션 서버)
  : 동적 콘텐츠(DB조회 등 비지니스 로직) 응답. 서블릿 컨테이너 역할 포함


HTTP요청 흐름
  1. 클라이언트에서 '이거 해줘'요청
  2. WAS가 서블릿 표준에 따라 HTTP요청을 해석
  3. WAS에서 DispatcherServlet로 요청 넘김
  4. 요청이 multipart/form-data(파일)이면 MultipartResolver로 파일과 일반 파라미터 분리
  5. URL, 메소드 기준으로 HandlerMapping을 통해 컨트롤러를 찾음
  6. HandlerAdapter가 해당 컨트롤러 샐행
  7. 파라미터 바인딩
    @RequestParam, @ModelAttribute : WebDataBinder
    @RequestBody : HttpMessageConverter
    MultipartFile : MultipartResolver
  8. 비지니스 로직 수행
  9. 응답 생성
    @RestController/@ResponseBody : HttpMessageConverter
    뷰 : ViewResolver
  10. 응답 반환 : DispatcherServlet가 클라이언트에게 반환

파라미터 바인딩 도구
  1. WebDataBinder : 요청 파라미터를 객체에 바인딩.
    @InitBinder으로 커스텀 에디터를 등록하거나, 전역 설정으로 바인딩 방식을 조절
  2. HttpMessageConverter : http body(JSON,XML 등)와 객체를 직렬화(객체->ResponseBody)/역직렬화
  3. MultipartResolver : multipart 담당
  4. 기타 : 특수 데이터 해석 전문

서브 도메인
  : 도메인 앞에 두어 웹 사이트의 영역을 구별하는 용도

URI (Uniform Resource Identifier)
  : 자원 식별자. 어떤 자원에 접근할지 식별함
  : URL + 쿼리 파라미터 = URI

메서드
	: 서버가 어떤 작업을 해 줬으면 해
	GET : 리소스 조회, body없음
	POST : 리소스 등록/생성	
	PUT : 리소스 전체 수정 (없으면 생성)
	PATCH : 리소스 일부 수정
	DELETE : 리소스 삭제, body없음


일반 헤더
	: 요청/응답 모두 사용
	Date : 생성 일시
	Connection : 연결 유지 여부
	Cache-Control : 캐시 동작 방식 설정
	Transfer-Encoding : 인코딩 방식

요청 헤더
	: 클라 -> 서버
	Authorization : 인증 토큰
	Accept : 클라가 받을 수 있는 데이터 타입
	Cookie : 서버에서 받은 쿠키

	Host : 요청 대상 도메인(필수)
	User-Agent : 브라우저/OS
	Accept-Encoding : 지원하는 압축 방식
	Refere : 직전 페이지 주소(쿼리스트링 포함)
	Origin : 직전 사이트 주소(쿼리스트링 미포함, CORS허용 여부 확인용)
	
응답 헤더
	: 서버 -> 클라
	Set-Cookie : 쿠키 구우라고 지시
	Location : 리다이렉트할 주소
	Access-Control-Allow-Origin : CORS 허용 출처

	Server : 서버 소프트웨어 정보
	WWW-Autheticate : 인증 요구(401 응답시)
	ETag : 리소스 버전 식별값
	Retry-After : 재요청까지 기다릴 시간
	
엔티티 헤더
	: 본문 데이터에 대한 정보
	Content-Type : 이 파일은 무슨무슨 종류야.(MIME 표기)
	Content-Disposition : 이 콘텐츠를 브라우저에서 이르케 처리해줘요
		ex) inline : 화면에 띄워줘요, attachment : 다운로드 해요

	Content-Length : 본문 크기
	Content-Encoding : 본문 압축 방식
	Content-Language : 본문 언어

상태 코드
	100-Continue : 요청 헤더를 받았으니 본문을 계속 보내도 됨
	101-Switching Protocols : WebSocket 전환 시 사용

	200-OK : 성공!
	201-Created : 리소스 생성 성공!
	204-No Content : 성공, 반환할 본문 없음

	301-Moved Permanently : 주소가 영구적으로 바뀜 (브라우저가 새 주소 기억)
	302-Found : 주소가 임시로 바뀜
	304-Not Modified : 캐시된 버전이 최신이므로 그걸 사용해도 됨

	400-Bad Request : 요청 형식이 잘못됨 (파라미터 오류 등)
	401-Unauthorized : 인증 안 됨 (로그인 필요)
	403-Forbidden : 인증은 됐지만 권한 없음
	404-Not Found : 요청한 리소스가 존재하지 않음
	405-Method Not Allowed : 해당 URL에서 그 HTTP 메서드(GET/POST 등)를 지원 안 함
	409-Conflict : 현재 상태와 충돌 (중복 데이터 등록 등)
	422-Unprocessable Entity : 형식은 맞지만 내용이 처리 불가 (유효성 검증 실패)
	429-Too Many Requests : 요청이 너무 많음 (API 호출 제한)

	500-Internal Server Error : 서버 내부 오류 (예외 터졌을 때)
	502-Bad Gateway : 프록시/게이트웨이가 잘못된 응답 받음
	503-Service Unavailable : 서버가 일시적으로 처리 불가 (점검, 과부하)
	504-Gateway Timeout : 프록시가 응답 대기 시간 초과
