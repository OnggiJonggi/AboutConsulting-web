공개키(비대칭)
    : 기밀성 높다. 누군가 암호문을 가로채도 못 읽음

대칭키
    : 암호화, 복호화에 동일한 키 사용

대칭/비대칭
    : 속도(연산할 데이터 양), 수신자 신뢰 여부, 확장성

블록 암호화
    : 평문을 블록으로 나눠 암호화

스트림 암호화
    : 비트(혹은 바이트) 단위로 암호화. RC4(요즘 잘 안씀)

AES(Advanced Encryption Standard)
    : 128, 192, 256 비트 블록 암호
    : 블록 길이가 길어질 경우
        - 연산량 증가. 암호문 조합(공간) 수가 늘어남
        - 패턴이 더욱 무작위가 됨
    1. ECB(Electronic Codebook) : 블럭 단위. 같은 평문 = 같은 암호문
    2. CBC(Cipher Block Chaining) : IV(이니셜 벡터) 필요.
        같은 IV + 평문 = 같은 암호문.
        IV가 달라지면 암호문도 바뀌기에 패턴 노출 최소화
    3. CFB(Cipher Feedback) : 블록을 스트림 암호화처럼 연속적(비트/바이트)으로 동작.
        이전 암호문 블록을 암호화 함수의 입력값으로 사용해서 키 스트림을 만든다.
        키 스트림(두 번째 블록부터. 첫 블록은 IV 사용), 복호화 키 사용해 복호화.
        실시간 통신용. 암호화 병렬 처리 불가. 복호화 병렬 처리 가능
    4. OFB(Output Feedback) : 블록을 연속적(비트/바이트) 암호화처럼 동작.
        이전 암호화 함수 출력값을 암호화 함수에 입력해 키 스트림을 만든다.
        CFB와 달리 키 스트림 생성에 암호문이 들어가지 않음.
        IV와 키를 알면 이전 암호문 블록을 몰라도 복호화 가능(키 스트림 예측 가능).
        실시간 통신용. 키 스트림 생성 병렬 처리 불가.
    5. CTR(Counter) : 실시간 미디어 전송. 병렬 처리 가능
    6. GCM(Galois/Counter Mode) : CTR + 데이터 인증(무결성)

암호 스트림
    : 키, IV, 카운터 값으로 암호화된 난수 비트열.
    : 암호 스트림과 암호문을 XOR연산해 평문으로 복호화.
    : 같은 키와 IV를 사용할 때 발생하는 패턴 노출 최소화.

RC4
    : 스트림 암호. 키에서 키 스트림을 뽑아냄(의사난수 바이트 생성기). 동기화 필수

동기화
    : 키 스트림을 동일한 순서와 상태로 생성되도록 송/수신자의 키, iv, 초기 상태값 등을 일치시킴

동기식 암호
    : 키 스트림을 송/수신자간 동기화
    : 키 스트림이 암호문과 별개로 생성됨
    : 동기화에 오류나면 치명적. 모든 암호문의 복호화에 영향
    : 암호문에 오류나면 상관없음

비동기식 암호
    : 키 스트림이 암호문 출력에 의존.
    : 이전 암호문 일부를 키 스트림 생성에 사용
    : 암호문 블럭 수신에 오류가 발생하더라고 몇 블록 후 손상되지 않는 블록만이 반영되면 정상 복호화

키 스트림
    : 평문과 XOR연산이 가능한 동일한 길이의 키값

XOR연산
    : 암호문과 키를 알면 평문을 알 수 있는 간단한 비트 연산
    : 복호화 할 때는 암호문에 XOR연산을 한번 더 해서 평문 생성
    : AND, OR연산에 비해 통계적 특성 없고 하드웨어 연산 더 쉬움

단방향 암호화
    : 복호화가 불가능한 고정 길이의 해시값 생성
    1. MD5 : 빠름. 충돌 취약성
    2. SHA(Secure Hash Algorithm)-1 : 충돌 취약성
    3. SHA-2 시리즈 : 다양한 비트 길이(224, 256, 384, 512)지원, 준 표준
    4. SHA-3 : 보안성 높은 채-신 택티껄.
    5. bcrypt : 패스워드 전용. 솔트 및 스트래칭 내장.
    : 충돌(collision) - 다른 문자열이 같은 해쉬값을 갖음.
        해시 함수 분석으로 충돌값 예측 가능한 충돌 취약성이 있을수도?
    : 솔트(salt) - 임의 무작위 값을 평문에 추가하고 암호화.
    : 스트레칭(Stretching) - 해시 연산을 정말정말 많이 해서 해시 연산 시간을 늘림.
        하나하나 때려맞추려면 그만큼 오래 걸려 보안성 높아짐.

HTTPS
    : SSL(Secure Sockets Layer)/TLS(Transport Layer Security)로 암호화해 통신

SSL
    : 관행적으로 SSL이라고 불리지만 현재는 후속인 TLS가 표준.
    : 암호화 키 + 인증 정보
    1. 클라가 서버에 접속 요청
    2. 서버가 공개키, 인증서 제공
    3. 클라가 인증서 유효성 검증
    4. 세션 키 교환
    5. 비대칭 암호화 통신 진행

CSRF(Cross-Site Request Forgery)
    : 서버가 조작된 요청을 정상 페이지에서 온 요청으로 착각
    1. 사용자는 사이트에 정상 접근해 세션/토큰 보유
    2. 공격자의 링크/스크립트 등 작동
    3. 사용자의 데이터가 사이트에 요청됨
    4. 서버는 정상 요청으로 판단하고 처리함
    해결 방법 : CSRF 토큰 등 1회용 값을 함께 포함하기, 헤더 검증

XSS(Cross-Site Scripting)
    : 입력값에 악성 스크립트 넣어 다른 사용자 정보 냠냠
    1. 사용자가 사이트 입력값에 스크립트 슛
    2. 출력될 때 스크립트가 실행됨
    3. 쿠키 탈취, 세션 하이재킹, 키 입력 감시, 가짜 폼 노출/유도 등등 털림
    해결 방법 : HTML이스케이프 등

UUID(Universally Unique Identifier)
    : 각 객체에 고유하게 부여되는 128비트 식별자
    : 버전 1 - 시간 기반 + MAC 주소.
        생성 시점과 생성 위치(노드/MAC주소) 추적 가능, 보안 취약. 고유성 우수.
    : 버전 2 - DCE(Security) 보안용, 시간 + 사용자/그룹ID.
        제한적 구현, POSIX UID/GID 포함, 주로 보안/인증용.
    : 버전 3 - 네임스페이스 + 이름(MD5 해시)
        동일 네임스페이스와 이름이면 항상 같은 UUID. URL, 도메인 등 네이밍 자원에 적합.
    : 버전 4 - 난수(Random) 기반으로 128비트 중 122비트 무작위
      	가장 많이 사용. 완전히 임의의 값, 추적 불가, 고유성·보안성 뛰어남.
        무작위로 생성되지 않은 비트 : UUID버전 및 variant(포맷과 인코딩 규칙) 정보
    : 버전 5 - 네임스페이스 + 이름(SHA-1 해시)
      	V3과 유사하나 해시 함수만 다름(MD5→SHA-1), 고정 생성, 해시 강도 보완.
    : 버전 6-8 - 타임스탬스 기반 정렬. 최신 버전

IDOR(Insecure Direct Object Reference)
	: 쿼리스트링 파라미터에 숫자 하나씩 바꿔 가며 요청
