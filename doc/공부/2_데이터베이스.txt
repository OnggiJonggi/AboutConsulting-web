데이터 베이스 특징
  1. 실시간 접근성
  2. 지속적 변화
  3. 동시 공유
  4. 내용에 의한 참조 - 참조할 때 주소/위치가 아닌 데이터 내용으로 검색

DDL(Data Definition Lang)
  : 데이터베이스 구조 정의
  : create, alter, drop

DML(Data Manipulation Lang)
  : 자료에 대한 언어
  : select, insert, update, delete

DCL(Data Control Lang)
  : 사용자의 접근 권한 등 보안 관리
  : grank, revoke

SELECT 쿼리 순서
  1. FROM
  2. ON/JOIN
  3. WHERE : 각 행 조건
  4. GROUP BY : 특정 컬럼을 기준으로 그룹지어 출력
  5. HAVING : 각 그룹 조건
  6. SELECT
  7. DISTINCT : 중복 제거(행의 모든 컬럼이 중복일때)
  8. ORDER BY
  9. LIMIT

TRIGGER
  : 특정 테이블에서 특정 DML이 수행되면 자동으로 소정의 행동을 하도록 작성된 프로그램

인덱스
  : 데이터 검색을 원활히 하려고 미리 정렬해둠.
  : 데이터 크기 작음 -> 페이지에 많은 인덱스 키가 들어감 -> 한 번에 많은 키 조회
  : 데이터 삽입, 수정, 삭제가 많으면 역효과

B-Tree
  : 자식 노드가 여러 개
  : B+Tree - 리프 노드(최하위 노드)를 연결해 순차 검색(범위 검색) 용이

해시 테이블
  : 키와 값을 인덱스에 저장
  1. 해시 함수로 키를 인덱스로 변환
  2. 인덱스 위치에 키와 값 저장
  3. 검색할 키를 해쉬 함수에 넣어 인덱스 변환
  4. 해당 인덱스에서 값 찾아냄
  : 단일 값 검색 성능 좋음

페이지
  : 메모리에서 데이터를 읽고 쓰는 최소 단위

정규화
  1. 하나의 칸에 하나의 데이터
  2. 복합 PK를 가진 테이블 컬럼은 모든 PK에 종속되어야 함
  3. PK가 아닌 컬럼에 종속되지 않아야 함
  : 데이터의 중복 방지
  : 테이블 구조 변경 시 구조 전체를 갈아없을 필요 없어 유지보수 용이
  : 원하는 조건의 데이터 조회 간편
  : JOIN구문이 많아져 조회 속도 느려

정규화 성능 향상 방법
  : 반정규화, 역정규화
  : 인덱스 최적화
  : 쿼리 JOIN 최적화

역정규화
  : 읽기작업이 많아 JOIN구문이 많이 쓰이는 곳에 사용

이상 현상
  : 삽입 이상 - 불필요한 정보도 입력해 NULL이 복사됨
  : 수정 이상 - 중복된 데이터의 일부만 수정됨
  : 삭제 이상 - 보존될 데이터까지 함께 삭제됨
  : 데이터 정규화로 해결

SQL Injection
  : 공격자가 입력값에 SQL구문을 삽입해 데이터베이스를 조작
  : 입력값에 대한 유효성 검사로 회피

관계형 데이터베이스(RDBMS)
  : 데이터를 행과 열로 이루어진 테이블에 저장
  : 스키마(구조 정의)에 따른 데이터 정의
  : 표준화된 SQL문법
  : 수평 확장성이 낮음
  : 데이터 구조가 명확할 때 사용됨

비관계형 데이터베이스(NoSQL)
  : 키-값, 그래프 등 다양한 방식으로 데이터 저장
  : 스키마가 거의 없어 유동적인 데이터 설계
  : 수평 확장성이 높음
  : 데이터 정확성을 직접 관리해야 함
  : 데이터 구조가 명확하지 않을 때 사용됨

스키마
  : DB구조와 제약 조건의 설계도
  : 데이터가 어떻게 저장/관리될지 정함

트랜잭션
  : DB에서의 작업 단위
  : 원자성 - 여러 개의 SQL문을 하나로 묶어 전부 성공하거나 전부 실패
  : 일관성 - 트랜잭션 전후 데이터가 항상 규칙에 맞게 유지됨
  : 고립성 - 각 트랜잭션은 다른 트랙잭션이 간섭 불가
  : 지속성 - 커밋 후에는 결과가 보존

DB Lock
  : 트랙잭션 처리의 순차성 보장
  : 공유락 - 데이터 읽기. 동시 접근 가능.
  : 베타락 - 데이터 쓰기. 동시 접근 불가능.

Elastic Search
  :  RDBMS의 LIKE와 달리 동의어, 유의어 검색 가능

옵티마이저
  : DBMS(데이터베이스 관리 시스템)내부에서 SQL을 가장 효율적으로 처리하게끔 실행 계획을 세우는 장치

DB튜닝
  : DB구조 등을 조정해 성능을 개선하는 작업
  1. DB설계 튜닝
  2. DBMS튜닝
  3. SQL튜닝

Inner JOIN
  : 교집합
  : 두 테이블에 모두 있어야 출력

Outer JOIN
  : 합집합
  : 두 테이블 중 하나만 있어도 출력

DELETE, TRUNCATE, DROP
  : DELETE - 롤백 가능, 일부 행만 지우기 가능, DML
  : TRUNCATE - 롤백 불가, 모든 행 삭제, DDL
  : DROP - 테이블 통채로 삭제, DDL

클러스트링
  : 여러 DB를 수평으로 구축. 동기식
  : 일관된 데이터, DB하나 고장나도 원할한 서비스
  : DB조회 부하 분산
  : 쓰기 성능 나쁨
  : 동기화 복잡해 확장 어려움

리플리케이션
  : 여러 DB를 수직으로 구축. Master 쓰기, Slave 읽기
  : Master 변경사항을 Slave로 동기화
  : 쓰기 성능 좋음
  : 비동기 특성 - 데이터 일관성 문제
  : 쓰기 성능 확장 어려움

WHERE, HAVING
  : WHERE - 개별 행 필터링. 그룹화 이전 필터링
  : HAVING - 그룹 필터링. 그룹화 후 필터링

COUNT
  : 테이블 행 반환
  : COUNT(*) - NULL 포함
  : COUNT(컬럼명) - NULL 미포함

varchar타입의 숫자 정렬
  : 알파벳순
  : ex) 1, 2, 10, 21, 3, 12 -> 1, 10, 12, 2, 21, 3

DB구축단계
  1. 요구사항 분석 - 무엇을 저장할지
  2. 개념 설계 - ERD처럼 어떤 데이터를 어떻게 연결할지 시각화
  3. 논리적 설계 - 정규화에 맞는 테이블 생성
  4. 물리적 설계 - 실제 저장 구조, 인덱스, 경로 등 물리적 사항
  5. 구현 및 테스트

DB 설계 원칙
  1. 데이터 무결성
  2. 정규화
  3. 적절한 키 설정
  4. 성능, 확장성 고려
  5. 보안
  6. 비지니스 요구사항 반영
  7. ERD 활용

멱등성
  : 같은 요청을 여러 번 보내도 결과가 같다
  GET : 몇 번 조회해도 서버 상태 변화 없음
  PUT : 같은 내용으로 여러 번 수정해도 결과 동일
  DELETE : 이미 삭제된 걸 또 삭제해도 결과 동일
  POST : 같은 요청을 두 번 보내면 데이터가 두 개 생길 수 있음
  PATCH : 경우에 따라 다름
