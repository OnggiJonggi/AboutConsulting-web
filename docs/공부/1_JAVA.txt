JAVA특징
  : 객체지향
  : 자바 가상머신(JVM) 사용 - 운영체제에 독립적, 실행 속도 느림

객체지향
  : 어떤 객체가 무엇을 할지 중심.
  : 특징 - 상속, 다형성, 추상화, 캡슐화 등등
  : 재사용성, 확장성, 유지보수성 좋음
  : SOLID 원칙 - 객체의 책임을 명확히 해 코드 관리를 유연하게 함
  : SRP - 단일 책임 원칙. 하나의 클래스에 하나의 책임
  : OCP - 개방-폐쇠 원칙. 확장에는 열리고 수정에는 닫혀야 함
  : LSP - 리스코프 치환 원칙. 하위 클래스를 상위 클래스로 대체해도 작동해야 함
  : ISP - 인터페이스 분리 원칙. 하나의 인터페이스에 최소한의 책임
  : DIP - 의존관계 역전 원칙. 구체적인 클래스보다 추상 클래스와 관계 맺기

절차지향
  : 순차적인 순서 중심.
  : 실행 순서가 빠름

캡슐화
  : 필드와 메서드를 하나의 객체로 묶음.
  : 외부에는 인터페이스만 노출, 내부 구현은 숨김
  : 안정성 - 외부에서 잘못된 사용으로 인한 오류 방지
      ex) 자동차를 운전할 때 자동차 부품 톱니바퀴 하나하나 조작하면 고장남
  : 유지보수 - 내부 구현이 바뀌어도 인터페이스가 그대로
  : 모듈성 - 각 객체는 자신의 역할만 담당하고 불필요한 다른 객체와 얽히지 않음

상속
  : 자식 클래스가 부모 클래스의 메소드를 물려받아 재사용
  : 코드 중복 최소화
  : 다형성을 이용한 유연한 코드

다형성
  : 부모 인터페이스로 자식 객체 처리
      ex) List<String> list = new ArrayList<>();
  : 코드 중복 최소화
  : 나중에 구현체를 바꿔야 할 때 한 줄만 수정해도 됨.

추상화
  : 실제 세계의 복잡한 데이터에서 필수 데이터만 단순화해 표현

자바 가상 머신(JVM)
  : OS에 맞게 자바를 해석
  : 가비지 컬렉션으로 메모리 관리

가비지 컬렉션
  : 필요 없는 메모리 회수. 메모리 관리

직렬화
  : JVM에 저장된 객체 -> 바이트 스트림
  : 파일/네트워크 등 외부 환경에 저장/전송 할 때 씀

serialVersionUID
  : 직렬화 버전 고정
  : 클래스 내용이 바뀌면 직렬화 버전이 달라질 수 있다.
  : 버전이 바뀌면 기존에 저장/전송된 데이터의 역직렬화에 문제 발생
  : 같은 구조라고 명시하는 신분증 역할.

기본 자료형(원시 타입)
  : 정수형 - byte(1), short(2), int(4), long(8)
  : 실수형 - float(4), double(8)
  : 문자형 - char(2)
  : 논리형 - boolean(1)

참조 자료형
  : 값이 담긴 주소값을 저장
  : 메모리 사용량 많음, null과 제네릭 사용 가능

오버라이딩
  : 상위 클래스의 메소드를 하위 클래스에서 재정의

오버로딩
  : 같은 이름의 메소드를 매개변수 수/타입을 바꾸어 여러 개 정의

try-with-resources
  : try-catch와 달리 자원을 자동으로 반납해주는 기능 탑재

불변 객체
  : 원시 타입에서 final키워드 사용
  : 동기화 고려할 필요 없음
  : 예외/오류 발생 시 피해 최소화

클래스 로딩 시점
  : 필요한 클래스를 그때그때 메모리에 올려 사용

클래스 초기화 시점
  : 인스턴스 생성
  : 클래스 정적 메소드 호출
  : 클래스 정적 변수 값 할당/사용

인스턴스
  : 클래스를 기반으로 실제 메모리에 생성된 객체

추상 클래스
  : 클래스 내 추상 메소드가 하나 이상 포함
  : 사용하려면 하위 클래스에서 상속받아 구현
  : 다중상속(여러 클래스를 동시 상속받음) 불가능
  : 목적 - 공통 기능을 아래로 확장

인터페이스
  : 모든 메소드가 추상 메소드
  : 사용하려면 하위 클래스에서 상속받아 구현
  : 다중상속(여러 인터페이스 동시 상속) 가능
  : 목적 - 동일한 동작 보장

싱글톤
  : 단 하나의 인스턴스만 사용
  : 목적 - 인스턴스가 하나만 존재해야 할 경우
  : 목적 - 동일한 인스턴스를 자주 생성하는 경우
  : ex) spring bean

메모리 영역
  : 메소드 - 전역변수, static변수. 프로그램 시작부터 끝까지
      JVM이 동작해서 클래스가 로딩될 때 할당됨
  : 스택 - 지역변수, 매개변수. 메소드 호출부터 종료까지
      메소드가 호출될 때 할당됨
  : 힙 - new키워드로 생성되는 객체, 배열. 가비지 컬렉션이 관리.
      런타임시 할당됨

생성자
  : 클래스와 같은 이름의 메소드.
  : 객체가 생성될 때 호출됨

Wrapper Class
  : 기본 자료형을 참조 자료형으로 바꾼 객체화 표현
  : Boxing - 기본 자료형 -> Wrapper Class
  : UnBoxing - Wrapper Class -> 기본 자료형

동기화
  : 여러 쓰레드가 하나의 자원을 사용하려고 시도하면, 하나의 쓰레드만 사용할 수 있게 제한
  : ex) count변수를 쓰레드가 공유해 카운트가 망가짐

쓰레드
  : 프로그램 내에서 독립 작동하는 작업 흐름

new String()
  : new키워드로 새로운 객체 생성 -> heap 메모리
  : 일반 방식("") -> heap 메모리 String pool에 저장됨

Stirng이 불변인 이유
  : Stirng pool에서의 재사용성
  : 여러 스레드가 동시에 참조하더라도 안전
  : 보안상 유리

StirngBuffer
  : 동기화 지원, 가변

StringBuilder
  : 동기화 미지원, 가변

접근 제한자
  : 필드와 메소드의 접근 범위
  : public - 제한 없음
  : potected - 해당 패키지, 상속받은 자식 클래스
  : (default) - 해당 패키지
  : private - 해당 클래스

클래스 변수 초기화 순서
  1. static 변수
  2. 필드 변수
  3. 생성자 블록

정적(static)
  : 인스턴스 생성 없이 사용 가능
  : 공통으로 사용되는 값 등 공용자원
  : 정적 필드는 인스턴스가 아닌 클래스 자체에 종속됨

내부 클래스(Inner Class)
  : 클래스 내부에 선언된 클래스
  : 관련 있는 클래스를 묶어 캡슐화

Error
  : 프로그램 실행 중 발생하는 치명적 오류
  : 발생 즉시 프로그램 종료됨

Checked Exception
  : RuntimeException 상속 안 받음
  : 예외 처리 필수. ex) 외부 자원 처리

Unchecked Exception
  : RuntimeException 상속받음
  : 예외 처리 선택.

리플렉션
  : 런타임 시점에서 현재 실행하는 클래스를 관찰/조작

Optional API
  : NullPointerException이 발생하지 않도록 도와주는 도구

컬렉션
  : 다수의 데이터를 관리하는 표준화된 클래스 집합
  : List - 순서 있음, 중복 가능. 노드가 다음 노드 주소값을 가짐
  : Set - 순서 없음, 중복 불가능 
  : Map - 키와 값, 키 중복 불가능. 키가 같으면 동일 객체

Set과 Map 중복 검사
  1. 해시코드(객체 식별값) 값이 같은지 확인
  2. 해시코드가 같다면 equls()메소드로 확인

제네릭
  : 데이터 타입을 지정해 잘못된 타입이 사용되는 문제 방지
  : 불공변성 - 제네릭 타입은 상속 관계와 무관하게 서로 다른 타입으로 취급

final
  : 클래스, 필드, 메소드 등에 선언되어 변경이 불가능한 상수

finally
  : try-catch에 사용되어 예외 처리와 무관하게 작동하는 코드가 담김

MVC
  : 데이터, 로직, 인터페이스의 관심사 분리
  1. Model - 데이터, 로직 관리
  2. View - UI. 사용자 인터페이스
  3. Controller - Model과 View를 연결
  : 협엽 효율화 - 디자이너는 View만, 개발자는 Model, Controller 담당
  : 유지보수성, 확장성

this
  : 현재 객체 자신
  : 멤버변수와 매개변수의 충돌 방지
  : 자기 자신 반환(생성자 체이닝)
  : 동일 클래스의 다른 생성자 호출
